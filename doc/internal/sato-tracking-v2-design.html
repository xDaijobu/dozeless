Sa.To Tracking v2

Konsep background tracking Sa.To yang bisa diandalkan: event apa saja yang dicatat, data apa saja yang diambil, permission yang dibutuhkan, dan apa yang terjadi kalau ada error.

1 · Tujuan & batasan

Yang mau dicapai

Diminta
  • Tracking benar-benar jalan di background, termasuk setelah HP restart.
  • Permission yang dipakai jelas: lokasi, baterai, dan lainnya.
  • Kejadian HP nyala dan HP mati/restart tercatat sebagai data.
  • Tracking berhenti/lanjut, app dimatikan paksa, dan jam HP diubah manual juga tercatat.
  • Data dipakai untuk audit salesman dan diagnosa teknis.
  • TrackingTable boleh diubah. Field yang sudah tidak bisa didapat (misalnya IMEI) dibuang.
Batasan
  • Tanpa notifikasi permanen, jadi tetap memakai alarm dan tidak memakai foreground service.
  • API pengiriman ke server (addTrackingV2.php) tidak diubah. Payload JSON akan berisi kolom baru dan tidak lagi berisi kolom IMEI.
  • Hanya Android. iOS tidak disentuh.
  • Event baru bisa dinyalakan per app. Sa.To menyalakannya, SM.To tetap seperti sekarang.

Alur satu alarm Get

  1. Alarm berbunyi. Jadwalkan Get berikutnya, lalu hitung AlarmDelaySec (jam sekarang dikurangi jadwal).
  2. PrerequisiteMonitor: kalau tidak siap, catat TRACKING_STOPPED, coba kirim data yang tertunda, tampilkan notifikasi, lalu batalkan job. Berhenti di sini.
  3. ProcessExitInspector: catat exit proses yang baru.
  4. Cek heartbeat. Kalau jaraknya dari Get terakhir lebih dari 3× interval (minimal 15 menit) dan HP tidak reboot, catat TRACKING_GAP.
  5. Catat LOCATION lewat recorder (GPS, geocode, snapshot), lalu perbarui heartbeat.
  6. Kalau Send sudah lewat jadwal (≥ interval Send), jalankan TrackingSender sekarang. Alarm Send tetap ada sebagai cadangan.

5 · Skenario

Apa yang tercatat di tiap kejadian

HP dimatikan normal

Kalau proses Sa.To sedang hidup, ACTION_SHUTDOWN menulis penanda waktu ke Preferences (cepat, tanpa SQLite). Kalau proses tidak hidup, tidak ada penanda.

→ saat boot: DEVICE_SHUTDOWN (SHUTDOWN / UNKNOWN) + DEVICE_BOOT

Baterai habis atau mati paksa

Tidak ada event yang bisa ditangkap. Saat boot, waktu mati diperkirakan dari heartbeat terakhir. Kalau baterai terakhir ≤ 3% dan tidak charging, reason-nya baterai habis.

→ DEVICE_SHUTDOWN (BATTERY_DEAD_LIKELY / UNKNOWN) + DEVICE_BOOT

Restart

Sama seperti HP dimatikan. Kalau jarak mati ke nyala kurang dari 3 menit, dianggap restart.

→ DEVICE_SHUTDOWN + DEVICE_BOOT (REBOOT)

Force stop dari Pengaturan

Android menghapus semua alarm dan tidak mengirim event apa pun sampai Sa.To dibuka lagi, bahkan setelah HP restart. Saat dibuka, exit info dibaca.

→ APP_FORCE_STOPPED (waktu exit) + TRACKING_GAP / TRACKING_RESUMED

Izin lokasi atau baterai dicabut

Terdeteksi di alarm berikutnya. Data yang tertunda dicoba dikirim, notifikasi "Tracking Sa.To berhenti, ketuk untuk memperbaiki" muncul, lalu job dibatalkan.

→ TRACKING_STOPPED (reason), lalu TRACKING_RESUMED setelah diperbaiki

Jam HP diubah manual

TIME_SET tetap dikirim walaupun app tertutup (kecuali setelah force stop). Penyesuaian kecil dari sinkronisasi jaringan (< 60 detik) diabaikan.

→ TIME_CHANGED / TIMEZONE_CHANGED

Offline lama

Get tetap mencatat lokasi dengan alamat kosong. Send gagal tapi baris tetap disimpan. Setelah online, data dikirim per batch sampai habis.

→ LOCATION (TrackingAddress kosong), tidak ada yang hilang

Ditahan Doze atau OEM

Alarm telat. AlarmDelaySec, IsDeviceIdle dan StandbyBucket di setiap baris menunjukkan penyebabnya.

→ LOCATION dengan delay, atau TRACKING_GAP kalau telatnya jauh
6 · TrackingTable

Perubahan kolom

Soal IMEI, sudah dicek

Sa.To memakai targetSdk 36 dan minSdk 23. Sejak Android 10, getImei(), getSerial() dan getSimSerialNumber() butuh READ_PRIVILEGED_PHONE_STATE, yang hanya diberikan ke app sistem dan device owner (MDM). App biasa akan mendapat SecurityException. Hanya HP Android 6–9 yang masih bisa membacanya. Karena itu ketiga kolom dibuang, dan identitas HP memakai ANDROID_ID di UUID untuk semua versi. ANDROID_ID tetap sama selama HP tidak di-factory reset dan app ditandatangani dengan key yang sama.

StatusKolomIsi / alasan
hapusDeviceIMEISlot1, DeviceIMEISlot2, DeviceSerialNumberTidak bisa didapat di Android 10+. Selama ini isinya ANDROID_ID.
perbaikiUUIDANDROID_ID di semua versi. Sebelumnya, Android 6–9 memakai hash dari IMEI dan SIM serial.
perbaikiLastLatitude, LastLongitudeFormat invariant (selalu titik desimal). Kosong kalau lokasi gagal, tidak lagi memakai nilai lama.
perbaikiCurrentTime, CurrentTimeZoneISO 8601 dengan offset (2026-10-29T13:05:05+07:00) dan ID zona (Asia/Jakarta), tanpa awalan teks.

SQLite di HP menambah kolom baru otomatis lewat CreateTable. Kolom yang dihapus dari model hanya tidak dipakai lagi, sehingga tidak perlu migrasi manual.

9 · Pengujian

Unit test + uji di HP via adb

Logika murni dibuat sebagai fungsi tanpa ketergantungan Android, supaya bisa di-unit test. Contohnya: perhitungan jendela mati, klasifikasi reason, deteksi gap, filter lompatan jam, pemetaan exit reason, batching dan hapus-per-id, serta rate limiter error. Sisanya diuji di HP:

adb logcat -s SaToTracking:V                                  # pantau selama uji
adb reboot                                                    # DEVICE_SHUTDOWN + DEVICE_BOOT (REBOOT)
adb shell am force-stop <pkg>  → buka Sa.To                  # APP_FORCE_STOPPED + TRACKING_RESUMED
adb shell pm revoke <pkg> android.permission.ACCESS_BACKGROUND_LOCATION   # TRACKING_STOPPED + notifikasi
adb shell dumpsys deviceidle whitelist -<pkg>                 # TRACKING_STOPPED (BATTERY_OPTIMIZED)
adb shell dumpsys deviceidle force-idle                       # AlarmDelaySec, IsDeviceIdle=Y
adb shell cmd connectivity airplane-mode enable               # offline: LOCATION tanpa alamat, Send ditunda

Dicek manual: tahan tombol power untuk mematikan HP (reason UNKNOWN atau SHUTDOWN), ubah jam di Pengaturan (TIME_CHANGED), dan matikan Autostart di HyperOS lalu restart (memastikan langkah wizard baru diperlukan).

11 · Keputusan terbuka

Perlu jawaban sebelum rencana implementasi

  1. Sa.To dirilis lewat Google Play atau APK internal/MDM? Kalau internal, QUERY_ALL_PACKAGES aman dipakai untuk daftar aplikasi fake GPS. Kalau lewat Play, permission ini perlu justifikasi dan kemungkinan ditolak.
  2. Server sanggup menerima payload baru? API tidak diubah, tapi JSON akan berisi kolom baru dan tidak lagi berisi kolom IMEI. Tolong pastikan dengan tim server bahwa addTrackingV2.php tidak error kalau ada key tambahan atau key yang hilang. Kolom baru baru tersimpan setelah server siap.
  3. Event untuk SM.To: default mati. Setuju?
  4. Langkah "Status Telepon" dihapus dari wizard. Setuju, dengan syarat tidak ada fitur lain yang butuh READ_PHONE_STATE?
