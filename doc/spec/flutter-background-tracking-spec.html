3 · Plugin bg_jobs

API Dart dan cara kerja native

// main.dart: dipanggil sekali saat app start
await BgJobs.initialize();                       // simpan handle dispatcher Dart

await BgJobs.schedule(
  id: 'get', callback: getJob,                   // top-level, @pragma('vm:entry-point')
  every: Duration(minutes: 5),
  requires: {Prereq.location, Prereq.backgroundLocation, Prereq.batteryUnrestricted},
  timeout: Duration(seconds: 45),
);
await BgJobs.schedule(id: 'send', callback: sendJob, every: Duration(minutes: 10),
  requires: {Prereq.batteryUnrestricted}, timeout: Duration(seconds: 45));

await BgJobs.cancel('get');
final s = await BgJobs.status('get');            // lastRun, nextRun, lastError, mode: exact|inexact|stopped
final p = await BgJobs.checkPrerequisites();     // dipakai wizard + saat app resume
await BgJobs.openSettings(Setting.batteryOptimization | appDetails | exactAlarm | autostart);
await BgJobs.runNow('get');                      // debug

Alur native saat alarm berbunyi

  1. JobReceiver.onReceive memanggil goAsync(). Wake lock broadcast tetap dipegang, ditambah exemption sementara ±10 detik dari sistem.
  2. Jadwalkan alarm berikutnya dulu dengan setExactAndAllowWhileIdle(RTC_WAKEUP). Kalau canScheduleExactAlarms() false, pakai setAndAllowWhileIdle dan ubah mode jadi inexact.
  3. Cek prasyarat job. Kalau ada yang kurang: panggil job sekali dengan trigger=prerequisiteLost supaya app sempat mencatat event, tampilkan notifikasi biasa, batalkan alarm job, set mode stopped.
  4. Ambil kunci per job. Kalau job yang sama masih jalan, catat skippedBusy dan selesai.
  5. Pastikan FlutterEngine background hidup (disimpan di cache, dipakai ulang antar alarm). Panggil dispatcher Dart, lalu dispatcher memanggil callback job.
  6. Tunggu callback selesai, dengan batas waktu (timeout). Ambil partial wake lock sendiri selama menunggu.
  7. Simpan status (lastRun, error), lepas wake lock, lalu pendingResult.finish().
Komponen nativeTugas
AlarmSchedulerAlarm exact sekali jalan per job id, fallback tidak-exact, isScheduled lewat PendingIntent.FLAG_NO_CREATE, menyimpan jadwal berikutnya
JobReceiverMenerima alarm job dan menjalankan alur di atas
WatchdogReceiversetInexactRepeating per jam, pengganti WorkManager. Kalau nextRun sebuah job lewat lebih dari 2× interval, alarmnya dipasang ulang dan job dijalankan dengan trigger=watchdog.
SystemEventReceiverDidaftarkan di manifest: BOOT_COMPLETED, QUICKBOOT_POWERON, MY_PACKAGE_REPLACED, TIME_SET, TIMEZONE_CHANGED. Boot dan update app memasang ulang semua alarm dan menjalankan job dengan trigger yang sesuai. Perubahan jam ditulis ke antrean systemEvents.
ProcessStartHookContentProvider di manifest plugin. onCreate-nya jalan setiap proses app hidup, termasuk saat dibangunkan alarm. Di sini receiver runtime ACTION_SHUTDOWN didaftarkan (Android 9+ hanya mengirim ke receiver runtime). Saat shutdown, penanda waktu ditulis ke SharedPreferences.
ExitInfoReaderMembaca getHistoricalProcessExitReasons (Android 11+) yang lebih baru dari yang terakhir dibaca, lalu dimasukkan ke systemEvents
DartRunnerEngine headless dan callback handle. Saat memulai isolate background, panggil DartPluginRegistrant.ensureInitialized() supaya package lain bisa dipakai.
4 · Baterai & izin

Baterai "Tidak dibatasi" adalah kunci di Android 12–14+

Kenapa wajib (dari dokumentasi resmi AlarmManager)

Di canScheduleExactAlarms(): app yang menargetkan Android 12+ hanya boleh memasang exact alarm kalau punya izin SCHEDULE_EXACT_ALARM atau berada di daftar pengecualian hemat daya, yaitu yang dicek dengan isIgnoringBatteryOptimizations.

Sejak Android 14, SCHEDULE_EXACT_ALARM ditolak secara default untuk app yang baru diinstal. Jadi di Android 14+, cara paling sederhana supaya alarm exact jalan adalah meminta user mengatur baterai app ke "Tidak dibatasi" (Unrestricted).

Dokumentasi setExactAndAllowWhileIdle juga menyebut alarm jenis ini normalnya dibatasi sekitar 1× per menit, dan saat Doze bisa jauh lebih jarang (contohnya 15 menit). Di uji referensi (HyperOS, baterai unrestricted, layar mati), Get dengan interval 1 menit tetap tepat waktu.

PrasyaratCara cek (native)Cara mintaKalau tidak ada
LokasiACCESS_FINE_LOCATIONDialog runtime (permission_handler)Job tracking berhenti
Lokasi backgroundACCESS_BACKGROUND_LOCATIONAndroid 11+: harus lewat Pengaturan, pilih "Izinkan sepanjang waktu"Job tracking berhenti
Baterai unrestrictedisIgnoringBatteryOptimizationsHalaman daftar optimasi baterai, atau App info → Baterai → Tidak dibatasiSemua job berhenti. Tanpa ini, exact alarm tidak boleh di Android 14+ dan alarm ditahan Doze.
Tidak di-restrictActivityManager.isBackgroundRestrictedApp info → Baterai (jangan pilih "Dibatasi")Semua job berhenti. Alarm app yang dibatasi tidak dijalankan di background.
Exact alarmcanScheduleExactAlarmsOtomatis true kalau baterai unrestricted. Cadangannya ACTION_REQUEST_SCHEDULE_EXACT_ALARM.Mode inexact: tetap jalan tapi jadwal bisa melenceng. Event ERROR ALARM_EXACT_DENIED.
NotifikasiPOST_NOTIFICATIONSDialog runtime (Android 13+)Tidak memblokir. User tidak diberi tahu kalau tracking berhenti.
Autostart (OEM)Tidak bisa dicek lewat APIBuka halaman Autostart merek HP (Xiaomi, Oppo, Vivo, Realme), lalu user konfirmasi sendiriDi HP merek tersebut, event boot tidak sampai ke app. Alarm baru terpasang lagi saat app dibuka.

Prasyarat dicek ulang setiap kali app di-resume (user kembali dari Pengaturan) dan di setiap alarm. Manifest plugin: RECEIVE_BOOT_COMPLETED, SCHEDULE_EXACT_ALARM, WAKE_LOCK. Manifest app: izin lokasi, INTERNET, ACCESS_NETWORK_STATE, POST_NOTIFICATIONS, dan android:installLocation tidak boleh preferExternal.

5 · Job Get & Send

Logika Dart yang diinjek

getJob

  1. Olah ctx.boot dan ctx.systemEvents menjadi baris event (bagian 6).
  2. Cek gap: kalau lastRunAt lebih lama dari 3× interval (minimal 15 menit) dan tidak ada reboot, catat TRACKING_GAP.
  3. Lokasi dengan geolocator: getCurrentPosition (akurasi tinggi, batas 5 detik). Kalau gagal, getLastKnownPosition (ditandai LAST_KNOWN). Kalau gagal juga, coba lagi 10 detik. Kalau tetap gagal, FAILED dengan koordinat kosong.
  4. Alamat dengan geocoding, dibatasi 3 detik. Kalau gagal, alamat kosong.
  5. Snapshot: battery_plus, connectivity_plus, device_info_plus, ditambah data dari ctx.
  6. Insert satu baris LOCATION.
  7. Kalau Send sudah lewat jadwal, jalankan sendJob sekarang. Ini mengatasi alarm Send yang digeser OEM.

sendJob

  1. Ambil maksimal N baris tertua (dari konfigurasi).
  2. Kirim lewat adapter app: Future<SendResult> upload(List<Record>).
  3. Kalau sukses, hapus berdasarkan id baris yang dikirim saja.
  4. Ulangi untuk batch berikutnya, maksimal 5 batch per jalan.
  5. Kalau gagal, baris tetap disimpan. Naikkan penghitung kegagalan. Setelah 6 kali gagal berturut-turut, catat ERROR SEND_FAILED_REPEATED (1× per jam).

Saat trigger=prerequisiteLost, sendJob tetap dicoba sekali supaya event TRACKING_STOPPED sampai ke server.

8 · Error

Prinsip: rantai alarm tidak boleh putus, dan baris tetap tersimpan

LapisanKalau gagalYang terjadi
PluginJob error atau melewati timeoutAlarm berikutnya sudah terpasang sejak langkah 2. Error disimpan ke status.lastError dan diteruskan ke job berikutnya lewat ctx.lastError.
PluginEngine Dart gagal start (handle hilang setelah update app)Catat ke status. Dicoba lagi di alarm berikutnya. Setiap kali app dibuka, initialize() menyimpan handle baru.
PluginExact alarm ditolakTurun ke setAndAllowWhileIdle, mode inexact
PluginPrasyarat hilangPanggil job sekali (prerequisiteLost), notifikasi, lalu berhenti. Saat app dibuka dan prasyarat lengkap lagi, alarm dipasang ulang dan job dipanggil dengan resumed.

JobUploadBaris tetap disimpan. Coba lagi di jadwal berikutnya atau saat Get melihat Send sudah lewat jadwal.
JobPenyimpanan > 20.000 barisHapus baris LOCATION tertua. Baris event tidak pernah dihapus. Catat STORAGE_TRIMMED.
9 · Uji kelayakan

Dikerjakan sebelum membangun semuanya

Plugin minimal: alarm exact berantai, receiver dengan goAsync, engine headless, dan callback yang ditunggu sampai selesai. Satu job Dart, setiap 1 menit, mengambil lokasi dengan geolocator lalu menulis ke sqflite. Diuji di HP HyperOS dengan baterai unrestricted.

UjiCaraLulus kalau
Layar mati 90 menitKunci HP, biarkan≥ 95% job jalan, median telat < 10 detik, semua baris punya lokasi
Proses dibunuhadb shell am kill <pkg> lalu tunggu alarmEngine cold start < 5 detik, job tetap selesai
Dozeadb shell dumpsys deviceidle force-idleAlarm tetap berbunyi, deviceIdle=true tercatat
Rebootadb rebootAlarm terpasang lagi tanpa membuka app, job boot jalan
Update app tanpa dibukaflutter install versi baru, jangan buka appJob tetap jalan (callback handle masih valid)
Wake lockJob sengaja await 20 detik saat layar matiJob selesai tanpa terpotong

Kalau "layar mati" atau "proses dibunuh" gagal, logika job dipindah ke Kotlin. API BgJobs.schedule tetap sama, hanya callback-nya diganti nama class Kotlin.

11 · Develop

Struktur repo dan alur debug

my_app/
  lib/                                  UI, wizard, halaman status
  packages/
    bg_jobs/                            flutter create --template=plugin --platforms=android
      lib/bg_jobs.dart                  API Dart + dispatcher (@pragma entry-point)
      android/src/main/AndroidManifest.xml   receiver, provider, permission → otomatis di-merge
      android/src/main/kotlin/...       AlarmScheduler, JobReceiver, WatchdogReceiver,
                                        SystemEventReceiver, ProcessStartHook, ExitInfoReader, DartRunner
    tracking_jobs/                      package Dart: getJob, sendJob, record, db, adapter
  pubspec.yaml   bg_jobs: {path: packages/bg_jobs}   tracking_jobs: {path: packages/tracking_jobs}
Dart

Hot reload hanya berlaku untuk UI. Callback job jalan di engine terpisah, jadi setelah mengubah job pakai hot restart, atau matikan proses supaya engine background dibuat ulang.

Kotlin

Setiap perubahan butuh stop lalu flutter run lagi. Untuk breakpoint, buka folder my_app/android di Android Studio (plugin muncul sebagai module), lalu Attach Debugger to Android Process.

Pantau

adb logcat -s BgJobs · adb shell dumpsys alarm · adb shell am get-standby-bucket <pkg> · menu debug "jalankan sekarang" dan "alarm 10 detik lagi"

Untuk dipakai di app lain: pindahkan packages/ ke repo sendiri, lalu tambahkan dependency git: dengan path: ke package-nya.

12 · Keputusan terbuka

Perlu jawaban sebelum rencana implementasi

  1. Nama plugin dan package. bg_jobs dan tracking_jobs masih nama sementara.
  2. Dirilis lewat Google Play atau internal/MDM? Ini menentukan dua hal: apakah QUERY_ALL_PACKAGES boleh dipakai untuk daftar aplikasi fake GPS, dan seberapa ketat review Play untuk background location dan exact alarm.
  3. Interval default Get dan Send, dan batas jumlah baris per batch.
  4. Teks notifikasi "tracking berhenti", dan apakah notifikasi itu boleh muncul berulang (misalnya 1× per hari) sampai masalahnya diperbaiki.
